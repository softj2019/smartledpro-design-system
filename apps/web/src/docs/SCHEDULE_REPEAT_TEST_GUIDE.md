# 반복 송출 테스트 가이드

## 📋 개요
반복 스케줄이 정상적으로 자동 실행되는지 확인하는 테스트 가이드입니다.

---

## 🎯 테스트 목표
1. ✅ 반복 스케줄이 설정한 시간에 자동으로 실행되는지 확인
2. ✅ 실행 로그가 정상적으로 기록되는지 확인
3. ✅ 전광판(/display/view)에 콘텐츠가 정상 표시되는지 확인
4. ✅ 우선순위 처리가 정확한지 확인

---

## 🧪 테스트 시나리오

### 1️⃣ 테스트용 템플릿 생성

**경로**: `/templates/new`

**설정값**:
```
이름: [테스트] 반복 송출 1분
제목: 반복 송출 테스트
본문: 이 메시지는 1분마다 자동으로 송출됩니다
카테고리: general
배경색: #1e3a8a (파란색)
```

**저장 후**:
- 템플릿 ID를 메모하세요 (예: `abc-123-def`)

---

### 2️⃣ 반복 스케줄 생성

**경로**: `/schedules/new`

#### ✅ **매일 반복 테스트**

**설정값**:
```
스케줄 이름: [테스트] 매일 반복
템플릿: [테스트] 반복 송출 1분
시작 날짜: 오늘
시작 시간: 현재 시간 + 2분
송출 시간: 5분
반복 유형: 매일
활성화: ✅ 체크
```

**예시**:
```
현재 시간: 14:30
설정 시간: 14:32 (2분 후)
→ 14:32, 14:33, 14:34... 매일 같은 시간에 반복
```

#### ✅ **매주 반복 테스트**

**설정값**:
```
스케줄 이름: [테스트] 매주 월수금
템플릿: [테스트] 반복 송출 1분
시작 날짜: 오늘
시작 시간: 09:00
송출 시간: 30분
반복 유형: 매주
요일 선택: 월, 수, 금
활성화: ✅ 체크
```

---

### 3️⃣ 자동 실행 모니터링

**경로**: `/test/schedule`

#### **모니터링 항목**:

1. **활성 반복 스케줄**
   - 생성한 스케줄이 목록에 표시되는지 확인
   - "곧 실행" 배지가 1분 이내 스케줄에 표시되는지 확인

2. **실행 로그**
   - 설정한 시간이 되면 자동으로 실행 로그가 추가되는지 확인
   - 성공/실패 상태가 정확한지 확인
   - 타임스탬프가 정확한지 확인

3. **자동 새로고침**
   - 10초마다 자동으로 데이터가 갱신되는지 확인
   - 체크박스를 끄면 자동 새로고침이 중지되는지 확인

4. **수동 실행**
   - "수동 실행" 버튼 클릭 시 즉시 스케줄이 체크되는지 확인
   - 대기 중인 스케줄이 즉시 실행되는지 확인

---

### 4️⃣ 전광판 표시 확인

**경로**: `/display/view`

#### **확인 사항**:

1. **콘텐츠 자동 갱신**
   - 스케줄 실행 시간에 콘텐츠가 자동으로 변경되는지 확인
   - 페이지 새로고침 없이 실시간으로 업데이트되는지 확인

2. **송출 시간**
   - 설정한 송출 시간(5분) 동안 표시되는지 확인
   - 시간 만료 후 자동으로 다음 콘텐츠로 전환되는지 확인

3. **우선순위 처리**
   - 여러 스케줄이 동시에 실행될 때 우선순위가 높은 것이 표시되는지 확인
   - Preview Studio에서 긴급 송출 시 즉시 전환되는지 확인

---

### 5️⃣ Audit Logs 확인

**경로**: `/audit-logs`

#### **필터 설정**:
```
Action: SCHEDULE_EXECUTED
날짜: 오늘
```

#### **확인 사항**:
1. 스케줄 실행 시마다 로그가 기록되는지 확인
2. 로그에 다음 정보가 포함되는지 확인:
   - 스케줄 ID
   - 템플릿 ID
   - 실행 시간
   - 사용자 정보
   - 실행 결과 (성공/실패)

---

## ⏱️ 자동 실행 시스템 설명

### **실행 주기**
```javascript
// useScheduleExecutor.ts
1분(60초)마다 자동으로 체크 및 실행
```

### **실행 조건**
```
1. is_active = true (활성화됨)
2. start_datetime <= 현재 시간 <= end_datetime
3. 반복 규칙(recurrence_rule)에 맞는 시간
4. last_executed_at이 없거나, 다음 실행 시간이 도달함
```

### **실행 프로세스**
```
1. 서버가 1분마다 POST /schedules/check-and-execute 호출
2. 실행 조건을 만족하는 스케줄 조회
3. manual_broadcasts 테이블에 INSERT
4. last_executed_at 업데이트
5. audit_logs에 실행 이력 기록
6. Realtime으로 /display/view에 즉시 반영
```

## 🐛 트러블슈팅

### ❌ **스케줄이 실행되지 않음**

**확인 사항**:
1. `is_active = true`인지 확인
2. `start_datetime`이 미래 시간이 아닌지 확인
3. `end_datetime`이 과거 시간이 아닌지 확인
4. 브라우저 콘솔에서 에러 확인
5. Debug Log Drawer에서 에러 로그 확인

**해결 방법**:
```
1. /test/schedule 페이지에서 "수동 실행" 클릭
2. 에러 메시지 확인
3. 스케줄 수정 페이지에서 설정 재확인
```

---

### ❌ **전광판에 표시되지 않음**

**확인 사항**:
1. `/display/view` 페이지가 열려 있는지 확인
2. Realtime 구독이 활성화되어 있는지 확인
3. manual_broadcasts 테이블에 데이터가 있는지 확인 (Debug Log)
4. 우선순위가 더 높은 다른 콘텐츠가 있는지 확인

**해결 방법**:
```
1. /display/view 페이지 새로고침
2. 브라우저 개발자 도구 > 네트워크 탭에서 Realtime 연결 확인
3. Preview Studio에서 즉시 송출로 테스트
```

---

### ❌ **반복이 작동하지 않음**

**확인 사항**:
1. `repeat_type`이 'none'이 아닌지 확인
2. `recurrence_rule`이 올바르게 저장되었는지 확인
3. 매주 반복의 경우 `days_of_week`가 있는지 확인

**해결 방법**:
```
1. 스케줄 수정 페이지에서 반복 설정 재확인
2. Debug Log Drawer에서 API 응답 확인
3. 새로운 스케줄로 다시 테스트
```

## 📊 테스트 체크리스트

### **기본 테스트**
- [ ] 템플릿 생성 완료
- [ ] 반복 스케줄 생성 완료
- [ ] 스케줄이 활성화(is_active=true) 상태
- [ ] 시작 시간이 올바르게 설정됨

### **자동 실행 테스트**
- [ ] 설정한 시간에 자동 실행됨
- [ ] 실행 로그에 기록됨
- [ ] last_executed_at 업데이트됨
- [ ] 전광판에 콘텐츠 표시됨

### **반복 테스트**
- [ ] 매일 반복 정상 동작
- [ ] 매주 반복 정상 동작
- [ ] 다음 실행 시간 정확함
- [ ] 종료 시간 이후 중지됨

### **모니터링 테스트**
- [ ] /test/schedule 페이지에서 상태 확인 가능
- [ ] 자동 새로고침 정상 동작
- [ ] 수동 실행 버튼 정상 동작
- [ ] 실행 로그 실시간 업데이트

### **우선순위 테스트**
- [ ] EMERGENCY(1000) > NOTICE(200) > WEATHER(100)
- [ ] 긴급 송출 시 즉시 전환
- [ ] 우선순위 낮은 콘텐츠는 대기
- [ ] 만료 시 다음 우선순위로 전환

## 🎯 성공 기준

### ✅ **테스트 통과 조건**

1. **자동 실행**
   - 설정한 시간에 ±1분 이내 실행
   - 100% 성공률 (5회 중 5회 성공)

2. **로그 기록**
   - 모든 실행이 audit_logs에 기록
   - 타임스탬프 정확도 99% 이상

3. **전광판 표시**
   - 실행 후 3초 이내 전광판에 표시
   - 송출 시간 정확도 ±5초 이내

4. **반복 정확도**
   - 매일/매주 반복이 예정대로 실행
   - 건너뛰는 일정 없음
