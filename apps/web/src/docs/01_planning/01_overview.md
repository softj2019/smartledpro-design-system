# 프로젝트 개요 및 정체성

## 1. 프로젝트 정체성

### 1.1 사업 기본 정보

| 항목 | 내용 |
|------|------|
| **사업명** | 체육공원 전광판 활용 개선 |
| **사업유형** | 고양 스마트시티 리빙랩 실증사업 |
| **주관기관** | 고양시 |
| **실증 지역** | 고양시 체육공원 |
| **실증 기간** | 2024년 (중간평가, 최종평가 포함) |
| **기술 스택** | Figma Make + Supabase + 공공데이터 API |

### 1.2 사업 배경

고양시는 시민들이 자주 이용하는 체육공원에 LED 전광판을 설치하여 운영하고 있으나, 다음과 같은 문제점이 발견되었습니다:

#### 현재 문제점
1. **콘텐츠 관리의 어려움**
   - 개발자 없이 콘텐츠 변경 불가
   - 기술적 지식 요구로 운영 부담 가중
   - 긴급 상황 대응 지연

2. **정보 전달의 한계**
   - 고정된 콘텐츠로 인한 시민 관심도 저하
   - 실시간 생활정보 부재
   - 재난·재해 시 즉각 대응 불가

3. **운영 효율성 문제**
   - 수동 관리로 인한 인력 낭비
   - 송출 이력 추적 불가
   - 증빙 자료 생성 어려움

### 1.3 실증 환경

#### 하드웨어 구성
- **LED 전광판**: 기존 설치된 옥외용 LED 디스플레이
- **MCU 제어보드**: 전광판 제어용 마이크로컨트롤러
- **네트워크**: 클라우드 기반 콘텐츠 송출

#### 소프트웨어 구성
- **프론트엔드**: Figma Make (React + Tailwind CSS)
- **백엔드**: Supabase (PostgreSQL + Edge Functions)
- **데이터 소스**: 기상청 API, AirKorea API
- **배포**: Vercel / Netlify (권장)

### 1.4 실증 목적

본 사업은 다음 목적을 달성하기 위해 추진됩니다:

#### 주요 목표
1. **시민 대상 생활·환경·안전 정보 전달**
   - 실시간 기상 정보 제공
   - 대기질(미세먼지) 정보 제공
   - 체육공원 이용 안내

2. **재난·재해 시 즉각적인 안내**
   - 긴급 메시지 우선 송출
   - 다중 전광판 일괄 제어
   - 송출 이력 자동 기록

3. **운영자의 관리 부담 최소화**
   - 노코드/로우코드 기반 콘텐츠 관리
   - 템플릿 기반 반복 운영
   - 미리보기 기능으로 오류 방지

4. **실증 결과를 타 지자체로 확산 가능한 구조 확보**
   - 표준화된 데이터 구조
   - 재사용 가능한 템플릿
   - 확장 가능한 아키텍처

## 2. 프로젝트 범위

### 2.1 포함 사항 (In-Scope)

#### 기능적 범위
- ✅ 전광판 콘텐츠 관리 시스템 (CMS)
- ✅ 실시간 미리보기 (Preview Studio)
- ✅ 템플릿 기반 메시지 생성
- ✅ 즉시/예약/반복 송출
- ✅ 긴급 메시지 송출 및 해제
- ✅ 공공데이터 자동 수집 (기상청, AirKorea)
- ✅ 전광판별 측정소 선택 기능
- ✅ 송출 우선순위 자동 처리
- ✅ 감사 로그 및 증빙 자료 생성
- ✅ 사용자 권한 관리 (RBAC + RLS)

#### 기술적 범위
- ✅ Supabase 데이터베이스 설계
- ✅ Supabase Edge Functions (ETL/Collector)
- ✅ Row Level Security (RLS) 정책
- ✅ Figma Make 기반 관리자 UI
- ✅ 전광판 송출 페이지 (`/display/{id}`)

#### 증빙 및 평가 범위
- ✅ 중간점검 대응 자료
- ✅ 중간평가 대응 자료
- ✅ 최종평가 대응 자료
- ✅ audit_logs 기반 CSV Export
- ✅ 실증 결과 리포트 생성

### 2.2 제외 사항 (Out-of-Scope)

#### 하드웨어 제어
- ❌ MCU 제어보드 펌웨어 개발
- ❌ 전광판 하드웨어 설치 및 유지보수
- ❌ 전원 및 통신 인프라 구축

#### 외부 시스템 연동
- ❌ 재난문자 API 직접 연동 (추후 확장 가능)
- ❌ 고양시 기존 행정시스템 연동
- ❌ 타 지자체 시스템 연동

#### 고도화 기능 (Phase 2)
- ❌ 동영상 콘텐츠 송출
- ❌ 인터랙티브 콘텐츠 (QR 코드 등)
- ❌ AI 기반 콘텐츠 자동 생성
- ❌ 모바일 앱 개발

## 3. 핵심 가치 제안 (Value Proposition)

### 3.1 운영자에게
- **개발자 없이 독립적으로 운영 가능**
- **실제 전광판과 동일한 미리보기 제공**
- **긴급 상황 즉시 대응 가능**

### 3.2 시민에게
- **실시간 생활정보 제공**
- **안전 정보 신속 전달**
- **체육공원 이용 편의 증대**

### 3.3 고양시에게
- **운영 비용 절감**
- **실증 증빙 자료 자동 생성**
- **타 지자체 확산 가능**

### 3.4 평가위원에게
- **명확한 기능 구현 확인**
- **실증 데이터 투명성 확보**
- **납품 판정 기준 명확**

## 4. 성공 기준 (Success Criteria)

### 4.1 기능적 성공 기준

다음 질문에 모두 **"예"**로 답할 수 있어야 합니다:

| # | 질문 | 검증 방법 |
|---|------|-----------|
| 1 | 개발자 도움 없이 운영자가 콘텐츠를 만들 수 있는가? | 템플릿 생성 시연 |
| 2 | 실제 전광판과 동일한 화면을 미리 볼 수 있는가? | Preview Studio 정확도 측정 |
| 3 | 지금/예약/반복/긴급 송출이 명확히 구분되는가? | UI 시연 및 로그 확인 |
| 4 | 공공데이터가 자동으로 들어오고 실패 시에도 안정적인가? | ETL 로그 및 Fallback 확인 |
| 5 | 누가, 언제, 무엇을 했는지 증빙이 남는가? | audit_logs CSV Export |

### 4.2 기술적 성공 기준

| 항목 | 기준 | 측정 방법 |
|------|------|-----------|
| **가용성** | 99.5% 이상 | Supabase 대시보드 |
| **데이터 수집 성공률** | 95% 이상 | ETL 로그 분석 |
| **미리보기 정확도** | 100% (픽셀 단위) | 육안 검증 + 스크린샷 |
| **긴급 송출 응답 시간** | 5초 이내 | 타이머 측정 |
| **감사 로그 누락률** | 0% | audit_logs 테이블 검증 |

### 4.3 사용성 성공 기준

| 항목 | 기준 |
|------|------|
| **학습 시간** | 운영자가 30분 이내 기본 기능 습득 |
| **오류 발생률** | 송출 오류 1% 미만 |
| **만족도** | 운영자 만족도 4.0/5.0 이상 |

### 4.4 실증 성공 기준

| 평가 단계 | 제출 자료 | 기준 |
|-----------|----------|------|
| **중간점검** | 기능 구현 현황, 초기 로그 데이터 | 핵심 기능 70% 이상 구현 |
| **중간평가** | 실증 데이터, 운영 로그, 사용자 피드백 | 실증 시나리오 80% 이상 검증 |
| **최종평가** | 최종 보고서, 전체 로그, 확산 계획 | 납품 판정 기준 100% 충족 |
