# 운영 시나리오 및 사용자 스토리

## 1. 사용자 역할 (User Roles)

### 1.1 역할 정의

| 역할 | 영문 | 권한 범위 | 주요 작업 |
|------|------|-----------|-----------|
| **시스템 관리자** | ADMIN | 전체 시스템 | 사용자 관리, 시스템 설정, 전광판 등록 |
| **운영자** | OPERATOR | 콘텐츠 관리 | 템플릿 생성, 송출 예약, 긴급 메시지 |
| **조회자** | VIEWER | 읽기 전용 | 대시보드 조회, 로그 조회 |

### 1.2 역할별 기능 매트릭스

| 기능 | ADMIN | OPERATOR | VIEWER |
|------|-------|----------|--------|
| Dashboard 조회 | ✅ | ✅ | ✅ |
| 템플릿 생성/수정/삭제 | ✅ | ✅ | ❌ |
| Preview Studio 사용 | ✅ | ✅ | ✅ (읽기) |
| 즉시 송출 | ✅ | ✅ | ❌ |
| 예약 송출 | ✅ | ✅ | ❌ |
| 긴급 송출 | ✅ | ✅* | ❌ |
| 긴급 해제 | ✅ | ✅* | ❌ |
| 전광판 등록/수정/삭제 | ✅ | ❌ | ❌ |
| 측정소 선택 | ✅ | ✅ | ❌ |
| Audit Logs 조회 | ✅ | ✅ | ✅ |
| CSV Export | ✅ | ✅ | ❌ |
| 사용자 관리 | ✅ | ❌ | ❌ |

**\*주의**: EMERGENCY 권한은 별도 플래그 (`can_emergency`)로 제어. OPERATOR 중 일부만 보유.

## 2. 핵심 시나리오

### 시나리오 1: 일상 공지 송출 (NOTICE)

#### 시나리오 설명
운영자가 "체육공원 방역 소독 안내" 메시지를 내일 오전 9시부터 12시까지 송출하려고 합니다.

#### 사용자 스토리
```
As an OPERATOR
I want to 템플릿을 만들고 예약 송출 설정하기
So that 특정 시간에 자동으로 공지가 전광판에 표시되도록
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | 로그인 | 이메일/비밀번호 입력 | Supabase Auth 인증 |
| 2 | Dashboard | "Templates" 메뉴 클릭 | 템플릿 목록 표시 |
| 3 | Templates | "새 템플릿" 버튼 클릭 | 템플릿 생성 폼 표시 |
| 4 | 템플릿 생성 | 제목: "방역 소독 안내"<br>본문: "오늘 오후 방역 소독 실시"<br>강조: "주차장 이용 제한"<br>색상: 파랑 선택 | 입력 필드 검증 |
| 5 | 템플릿 생성 | "저장" 버튼 클릭 | message_templates INSERT<br>audit_logs 기록 |
| 6 | Templates | 생성된 템플릿 클릭 | 상세 화면 표시 |
| 7 | 템플릿 상세 | "Preview Studio로 열기" 버튼 클릭 | Preview Studio 진입 |
| 8 | Preview Studio | 우측 미리보기에서 실제 화면 확인 | 실시간 렌더링 |
| 9 | Preview Studio | "예약 송출" 탭 클릭 | 날짜/시간 선택 UI 표시 |
| 10 | Preview Studio | 시작: 내일 09:00<br>종료: 내일 12:00<br>대상: "공원 정문 전광판" 선택 | 입력 검증 |
| 11 | Preview Studio | "예약 송출" 버튼 클릭 | schedules INSERT<br>audit_logs 기록<br>성공 메시지 표시 |
| 12 | Schedules | "Schedules" 메뉴에서 확인 | 예약 목록에 표시<br>캘린더 뷰에 마커 표시 |

#### 예상 결과
- 내일 09:00에 자동으로 전광판에 메시지 표시
- schedules 테이블에 레코드 저장
- audit_logs에 "SEND" 행위 기록

#### 검증 기준
- [ ] 템플릿 생성 3분 이내 완료
- [ ] Preview Studio 미리보기 정확도 100%
- [ ] 예약 시간에 정확히 송출 (오차 ±10초)
- [ ] audit_logs에 기록 확인

### 시나리오 2: 긴급 메시지 송출 (EMERGENCY)

#### 시나리오 설명
폭염주의보가 발령되어 긴급 안내 메시지를 전체 전광판에 즉시 송출해야 합니다.

#### 사용자 스토리
```
As an OPERATOR with EMERGENCY permission
I want to 긴급 메시지를 즉시 송출하기
So that 모든 전광판에서 긴급 안내를 표시하여 시민 안전을 확보
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | Dashboard | "긴급 송출" 버튼 클릭 (빨강 강조) | 긴급 송출 모달 표시 |
| 2 | 긴급 송출 모달 | 제목: "폭염주의보"<br>본문: "무더위로 인한 온열질환 주의"<br>강조: "외출 자제 바랍니다" | 입력 검증 (간소화) |
| 3 | 긴급 송출 모달 | "전체 전광판 송출" 확인 (기본 선택) | 활성 전광판 목록 표시 |
| 4 | 긴급 송출 모달 | "긴급 송출" 버튼 클릭 | 확인 다이얼로그 표시<br>"이 작업은 모든 전광판의 현재 송출을 중단합니다. 계속하시겠습니까?" |
| 5 | 확인 다이얼로그 | "확인" 클릭 | display_state 전체 업데이트<br>priority=300, content_type=EMERGENCY<br>audit_logs "EMERGENCY_SEND" 기록 |
| 6 | Dashboard | 성공 메시지 표시<br>"긴급 메시지가 전체 전광판에 송출되었습니다." | 긴급 송출 상태 배지 표시 |
| 7 | 송출 페이지 | 전광판에서 긴급 메시지 확인 | `/display/{id}` 자동 업데이트 (5초 이내) |

#### 예상 결과
- 모든 전광판에 즉시 긴급 메시지 표시
- 기존 NOTICE/WEATHER 송출 중단
- audit_logs에 "EMERGENCY_SEND" 기록
- Dashboard에 긴급 송출 상태 표시

#### 검증 기준
- [ ] 긴급 송출 버튼 클릭부터 전광판 반영까지 5초 이내
- [ ] 모든 전광판 동시 반영 확인
- [ ] audit_logs에 user_id, timestamp, action_detail 기록
- [ ] 우선순위 300으로 설정 확인

### 시나리오 3: 긴급 메시지 해제

#### 시나리오 설명
폭염주의보가 해제되어 긴급 메시지를 해제하고 이전 상태로 복원합니다.

#### 사용자 스토리
```
As an ADMIN or OPERATOR with EMERGENCY permission
I want to 긴급 메시지를 해제하기
So that 이전에 송출 중이던 일반 공지나 기상 정보로 복원
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | Dashboard | 긴급 송출 상태 배지 확인<br>"긴급 메시지 송출 중" (빨강) | "긴급 해제" 버튼 표시 |
| 2 | Dashboard | "긴급 해제" 버튼 클릭 | 확인 다이얼로그 표시<br>"긴급 메시지를 해제하시겠습니까?" |
| 3 | 확인 다이얼로그 | "확인" 클릭 | display_state에서 EMERGENCY 레코드 삭제<br>이전 NOTICE/WEATHER 자동 복원<br>audit_logs "EMERGENCY_RELEASE" 기록 |
| 4 | Dashboard | 성공 메시지 표시<br>"긴급 메시지가 해제되었습니다." | 긴급 송출 상태 배지 제거 |
| 5 | 송출 페이지 | 전광판에서 이전 콘텐츠 복원 확인 | priority 200 또는 100 콘텐츠 표시 |

#### 예상 결과
- EMERGENCY 레코드 삭제
- 이전 NOTICE (있는 경우) 또는 WEATHER로 자동 복원
- audit_logs에 "EMERGENCY_RELEASE" 기록

#### 검증 기준
- [ ] 해제 후 5초 이내 이전 콘텐츠 복원
- [ ] audit_logs에 해제 시각 기록
- [ ] 복원된 콘텐츠 정확성 확인

### 시나리오 4: 측정소 변경 및 데이터 반영

"공원 정문 전광판"의 공기질 측정소를 "일산동구"에서 "일산서구"로 변경합니다.

#### 사용자 스토리
```
As an OPERATOR
I want to 전광판별 공기질 측정소를 선택하기
So that 해당 전광판 위치에 가장 가까운 측정소 데이터를 표시
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | Displays | "공원 정문 전광판" 선택 | 상세 화면 표시 |
| 2 | Display 상세 | "공기질 측정소 변경" 버튼 클릭 | 측정소 선택 모달 표시 |
| 3 | 측정소 선택 모달 | 검색: "일산"<br>시도: "경기" 선택 | air_stations 필터링 |
| 4 | 측정소 선택 모달 | 결과 목록 확인:<br>- 일산동구 (현재 선택)<br>- 일산서구<br>- 일산3동 | 각 측정소 상태 표시<br>(정상/지연/실패) |
| 5 | 측정소 선택 모달 | "일산서구" 선택 | 선택 하이라이트 |
| 6 | 측정소 선택 모달 | "적용" 버튼 클릭 | display_config UPDATE<br>air_station_id 변경<br>audit_logs 기록 |

#### 예상 결과
- display_config.air_station_id 업데이트
- 다음 수집 주기(10분 이내)에 새 측정소 데이터 자동 수집
- Preview Studio 및 송출 페이지에 반영

#### 검증 기준
- [ ] 측정소 변경 후 display_config 즉시 업데이트
- [ ] 10분 이내 새 측정소 데이터 수집 확인
- [ ] audit_logs에 변경 이력 기록

### 시나리오 5: 반복 송출 설정 (매주 월요일 운동 프로그램 안내)

#### 시나리오 설명
매주 월요일 오전 8시~10시에 "운동 프로그램 안내" 메시지를 자동 송출합니다.

#### 사용자 스토리
```
As an OPERATOR
I want to 매주 반복 송출 설정하기
So that 매번 수동으로 예약하지 않고 자동으로 송출
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | Templates | "운동 프로그램 안내" 템플릿 선택 | 상세 화면 표시 |
| 2 | 템플릿 상세 | "Preview Studio로 열기" 클릭 | Preview Studio 진입 |
| 3 | Preview Studio | "반복 송출" 탭 클릭 | 반복 규칙 설정 UI 표시 |
| 4 | 반복 송출 설정 | 반복 주기: "매주" 선택<br>요일: "월요일" 체크<br>시작 시각: 08:00<br>종료 시각: 10:00 | 입력 검증 |
| 5 | 반복 송출 설정 | 미리보기 캘린더 확인<br>"다음 4주간 월요일에 표시됩니다" | 시각적 확인 |
| 6 | 반복 송출 설정 | "반복 송출" 버튼 클릭 | schedules INSERT<br>recurrence_rule JSON 저장<br>audit_logs 기록 |
| 7 | Schedules | 캘린더 뷰에서 확인 | 매주 월요일 8-10시에 마커 표시 |

#### recurrence_rule 예시 (JSON)
```json
{
  "frequency": "WEEKLY",
  "byday": ["MO"],
  "start_time": "08:00",
  "end_time": "10:00",
  "timezone": "Asia/Seoul"
}
```

#### 예상 결과
- 매주 월요일 08:00에 자동 송출
- schedules.recurrence_rule에 규칙 저장
- Edge Function (Cron)에서 매주 자동 실행

#### 검증 기준
- [ ] 첫 월요일 08:00 정확히 송출
- [ ] 4주 연속 송출 확인
- [ ] audit_logs에 매주 기록 확인

### 시나리오 6: 충돌 경고 및 처리

#### 시나리오 설명
기존에 예약된 "방역 안내" (14:00~15:00)와 겹치는 시간대에 "행사 안내" (14:30~16:00)를 예약하려고 합니다.

#### 사용자 스토리
```
As an OPERATOR
I want to 시간 충돌 시 경고를 받기
So that 의도치 않은 송출 중복을 방지
```

#### 단계별 흐름

| 단계 | 화면 | 사용자 행위 | 시스템 동작 |
|------|------|-------------|-------------|
| 1 | Preview Studio | "행사 안내" 템플릿 로드 | 미리보기 표시 |
| 2 | 예약 송출 설정 | 시작: 오늘 14:30<br>종료: 오늘 16:00<br>대상: "공원 정문 전광판" | 입력 검증 |
| 3 | 예약 송출 설정 | "예약 송출" 버튼 클릭 | 충돌 검사 쿼리 실행 |
| 4 | 충돌 경고 다이얼로그 | **경고 메시지 표시**<br>"14:00~15:00에 '방역 안내'가 예약되어 있습니다.<br>시간이 겹칩니다. 계속하시겠습니까?"<br><br>옵션:<br>- 기존 예약 보기<br>- 시간 수정<br>- 무시하고 계속 | 사용자 선택 대기 |
| 5 | 충돌 경고 다이얼로그 | "무시하고 계속" 선택 | schedules INSERT<br>audit_logs에 "CONFLICT_IGNORED" 플래그 기록 |
| 6 | Schedules | 캘린더 뷰에서 두 예약 모두 표시 | 겹치는 시간대 다른 색상으로 표시 |

#### 실제 송출 동작
```
14:00 - 방역 안내 송출 시작 (priority=200)
14:30 - 행사 안내 송출 시작 (priority=200)
       → 나중에 생성된 스케줄이 우선 (updated_at DESC)
15:00 - 방역 안내 종료
16:00 - 행사 안내 종료
```

#### 예상 결과
- 충돌 경고 표시
- 사용자 확인 후 진행
- 14:30부터 "행사 안내" 표시 (방역 안내 덮어씀)

#### 검증 기준
- [ ] 충돌 검사 로직 정확성
- [ ] 경고 메시지 명확성
- [ ] audit_logs에 충돌 플래그 기록

```
So that 중간평가 보고서에 증빙 자료로 첨부
```

#### 단계별 흐름

| 1 | Dashboard | "Audit Logs" 메뉴 클릭 | 감사 로그 테이블 표시 |
| 2 | Audit Logs | 날짜 범위 선택:<br>시작: 2024-05-01<br>종료: 2024-05-31 | 필터링된 로그 표시 |
| 3 | Audit Logs | 필터 추가:<br>Action: "SEND", "EMERGENCY_SEND"<br>Resource: "display_state" | 송출 행위만 필터링 |
| 4 | Audit Logs | "CSV 내보내기" 버튼 클릭 | CSV 생성 시작 |
| 5 | 다운로드 | 파일 다운로드<br>`audit_logs_2024-05-01_2024-05-31.csv` | UTF-8 BOM 인코딩<br>Excel 호환 |
| 6 | Excel | 파일 열기 | 한글 깨짐 없이 표시<br>컬럼: created_at, user_email, action, resource_type, action_detail |

#### CSV 예시
```csv
created_at,user_email,user_role,action,resource_type,action_detail
2024-05-01 09:00:15,operator@goyang.go.kr,OPERATOR,SEND,display_state,"{'display_ids': ['uuid'], 'content_type': 'NOTICE'}"
2024-05-01 14:30:22,admin@goyang.go.kr,ADMIN,EMERGENCY_SEND,display_state,"{'message': '폭염주의보', 'display_ids': 'all'}"
2024-05-01 16:00:05,admin@goyang.go.kr,ADMIN,EMERGENCY_RELEASE,display_state,"{}"
```

#### 예상 결과
- Excel 호환 CSV 파일 생성
- 한글 깨짐 없음
- 중간평가 보고서에 즉시 활용 가능

#### 검증 기준
- [ ] CSV Export 3초 이내 완료
- [ ] UTF-8 BOM 인코딩 적용
- [ ] Excel에서 한글 정상 표시
- [ ] 날짜 형식 정확 (YYYY-MM-DD HH:MI:SS)

## 3. 예외 상황 시나리오

### 예외 시나리오 1: 공공데이터 API 장애

#### 상황
기상청 API가 30분 동안 응답하지 않습니다.

#### 시스템 동작
1. Edge Function에서 2회 재시도 (각 5초 대기)
2. 최종 실패 시 마지막 성공 데이터 유지
3. Dashboard에 "데이터 지연" 상태 표시 (노랑)
4. 운영자에게 알림 (선택 사항)

#### 사용자 경험
- 전광판에 마지막 성공 데이터 계속 표시
- "30분 전 업데이트 (지연)" 텍스트 표시
- 정상 복구 시 자동으로 최신 데이터로 갱신

#### 검증 기준
- [ ] Fallback 데이터 표시 확인
- [ ] "지연" 상태 표시 확인
- [ ] 복구 후 자동 갱신 확인

---

### 예외 시나리오 2: 권한 없는 사용자의 긴급 송출 시도

#### 상황
VIEWER 역할 사용자가 긴급 송출 버튼에 접근하려고 시도합니다.

#### 시스템 동작
1. UI에서 긴급 송출 버튼 비활성화 (또는 숨김)
2. 만약 API 직접 호출 시도 시:
   ```
   HTTP 403 Forbidden
   {
     "error": "You do not have permission to perform EMERGENCY_SEND"
   }
   ```
3. Supabase RLS 정책에서 차단
4. audit_logs에 "UNAUTHORIZED_ATTEMPT" 기록

#### 검증 기준
- [ ] UI에서 버튼 비활성화 확인
- [ ] API 호출 차단 확인
- [ ] audit_logs에 시도 기록

---

### 예외 시나리오 3: 전광판 오프라인 상태

#### 상황
"공원 후문 전광판"이 네트워크 장애로 오프라인 상태입니다.

#### 시스템 동작
1. displays.is_active = false 설정 (수동 또는 자동)
2. 데이터 수집 대상에서 제외
3. Dashboard에 "오프라인" 배지 표시
4. 송출 대상 선택 시 비활성화

#### 사용자 경험
- Displays 목록에서 "오프라인" 상태 확인
- 송출 대상 선택 시 선택 불가
- 복구 후 is_active = true 설정 → 자동으로 수집 재개

#### 검증 기준
- [ ] 오프라인 전광판 수집 제외 확인
- [ ] Dashboard 상태 표시 확인
- [ ] 복구 후 자동 재개 확인

## 4. 통합 시나리오 (End-to-End)

### 통합 시나리오: 실증사업 평가 당일

#### 배경
평가위원이 방문하여 전체 시스템을 시연합니다.

#### 시연 순서 (30분)

| 시간 | 단계 | 시연 내용 | 검증 항목 |
|------|------|-----------|-----------|
| 0-5분 | 로그인 및 Dashboard | - OPERATOR 계정 로그인<br>- Dashboard 개요 확인<br>- 최근 송출 이력 확인 | - 로그인 정상<br>- Dashboard 로딩 3초 이내 |
| 5-10분 | 템플릿 생성 | - "평가위원 환영" 템플릿 생성<br>- Preview Studio 미리보기 | - 템플릿 생성 3분 이내<br>- 미리보기 정확도 100% |
| 10-15분 | 즉시 송출 | - "지금 송출" 버튼 클릭<br>- 전광판에서 실제 확인 | - 5초 이내 전광판 반영 |
| 15-20분 | 긴급 송출 | - "평가 진행 중" 긴급 메시지 송출<br>- 모든 전광판 확인 | - 전체 전광판 동시 반영<br>- 우선순위 300 확인 |
| 20-22분 | 긴급 해제 | - 긴급 메시지 해제<br>- 이전 상태 복원 확인 | - 5초 이내 복원 |
| 22-25분 | 측정소 변경 | - 공기질 측정소 변경<br>- Preview Studio 반영 확인 | - 즉시 반영 확인 |
| 25-28분 | Audit Logs 확인 | - 전체 행위 로그 확인<br>- 필터링 및 검색 | - 모든 행위 기록 확인 |
| 28-30분 | CSV Export | - audit_logs CSV 내보내기<br>- Excel에서 열기 | - 한글 깨짐 없음<br>- 보고서 첨부 가능 |

#### 평가 체크리스트

**기능 검증**
- [ ] 로그인 정상
- [ ] 템플릿 생성 완료
- [ ] Preview Studio 정확도 100%
- [ ] 즉시 송출 5초 이내 반영
- [ ] 긴급 송출 전체 전광판 반영
- [ ] 긴급 해제 및 복원
- [ ] 측정소 변경 반영
- [ ] Audit Logs 전체 기록
- [ ] CSV Export 성공

**비기능 검증**
- [ ] UI 반응 속도 (3초 이내)
- [ ] 오류 메시지 한글 표시
- [ ] 브라우저 호환성 (Chrome, Safari)
- [ ] 모바일 반응형 (선택 사항)

**증빙 자료**
- [ ] audit_logs CSV 파일
- [ ] 송출 스크린샷 (실제 전광판)
- [ ] 우선순위 검증 로그
- [ ] 데이터 수집 성공률 통계
